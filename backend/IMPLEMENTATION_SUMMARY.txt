===============================================
API ENDPOINTS SPECIFICATION
===============================================

1. CREATE GIG (POST /api/gigs)
   Input: Gig data (title, description, category, budget, deadline, etc.)
   Output: Created gig with PENDING status
   Auth: Required
   Status: 201 Created

2. LIST GIGS (GET /api/gigs)
   Input: Filters (status, category), pagination (page, limit), search
   Output: Paginated list of gigs
   Auth: Not required
   Status: 200 OK
   Features: Full-text search, filtering, sorting, pagination

3. GET SINGLE GIG (GET /api/gigs/:id)
   Input: Gig ID
   Output: Complete gig details with populated references
   Auth: Not required
   Status: 200 OK or 404 Not Found

4. UPDATE GIG STATUS (PATCH /api/gigs/:id)
   Input: Status (APPROVED/REJECTED), optional rejection reason
   Output: Updated gig
   Auth: Required (admin only)
   Status: 200 OK
   Validation: Only PENDING gigs can be updated

5. GET CREATOR'S GIGS (GET /api/gigs/creator/:creatorId)
   Input: Creator ID, optional status filter, pagination
   Output: Paginated list of creator's gigs
   Auth: Not required
   Status: 200 OK

===============================================
GIG STATUS FLOW
===============================================

Creation:
User creates gig → Status: PENDING

Admin Review:
PENDING → APPROVED (goes live)
PENDING → REJECTED (not accepted)

Lifecycle:
APPROVED → IN_PROGRESS (creator starts work)
IN_PROGRESS → COMPLETED (work finished)
Any → CANCELLED (cancelled by owner/admin)
