===============================================
GIG STRUCTURE
===============================================

Each gig contains:

Core Content:
- id: Unique identifier
- title: Gig title (5-100 chars)
- description: Full description (20-5000 chars)
- category: Type of gig (10 categories)
- budget: Budget amount (float)
- deadline: Submission deadline (ISO datetime)

Status & Management:
- status: Current status (6 possible values)
- creator_id: Creator's user ID
- selected_creator_id: Selected creator (if any)
- rejection_reason: Reason if rejected

Details:
- attachments: Array of attachment URLs
- requirements: Detailed requirements (2000 chars max)
- target_audience: Target description (500 chars max)
- skills_required: Array of required skills
- applications_count: Number of applications

Metadata:
- created_at: Creation timestamp (auto)
- updated_at: Update timestamp (auto)
- approved_at: Approval timestamp (admin)
- approved_by: Admin ID (admin)
- rejected_at: Rejection timestamp (admin)
- rejected_by: Admin ID (admin)
- notes: Admin notes (optional)

===============================================
GIG STATUS FLOW
===============================================

Creation:
creator creates gig → status: pending_approval

Admin Review:
pending_approval → approved (goes live)
pending_approval → rejected (not accepted)

Lifecycle:
approved → in_progress (work starts)
in_progress → completed (work finished)
any status → cancelled (cancelled)

===============================================
ENDPOINT USAGE SUMMARY
===============================================

CREATE GIG:
POST /api/gigs
Headers: Authorization: Bearer <token>
Body: Gig data with all required fields
Response: 201 Created with gig details

LIST GIGS:
GET /api/gigs?status=approved&page=1&limit=10
Response: 200 OK with gig list and pagination

GET SINGLE GIG:
GET /api/gigs/{gig_id}
Response: 200 OK or 404 Not Found

APPROVE GIG (ADMIN):
PATCH /api/gigs/{gig_id}?action=approve
Headers: Authorization: Bearer <admin_token>
Response: 200 OK with updated gig

REJECT GIG (ADMIN):
PATCH /api/gigs/{gig_id}?action=reject
Headers: Authorization: Bearer <admin_token>
Body: { "rejection_reason": "..." }
Response: 200 OK with updated gig

GET CREATOR GIGS:
GET /api/gigs/creator/{creator_id}
Response: 200 OK with creator's gigs
